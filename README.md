# STE Slicer — AI Assistant Team

Чистовая папка для установки и проверки проекта на Windows с Stereotech STE
Slicer 7.10. Папка плагина и его внутренние имена уже имеют требуемый вид.
**Не переименовывайте `AIAssistantTeam`, Python-модули, QML-файлы и ключи
настроек.**

## Состав

```text
final_submission/
├── AIAssistantTeam/               # готовая папка плагина STE Slicer
├── scripts/
│   ├── pipeline_runner.py         # пакетный MCP-прогон
│   ├── pipeline_models.example.json
│   ├── run_pipeline.ps1
│   └── requirements.txt
├── inputs/
│   ├── 01-gear/model.stl
│   ├── conveyor-wheel/model.stl
│   └── simple-cylinder/model.stl
└── results/
    └── 01-gear/
        ├── project.3mf
        ├── result.gcode
        └── pipeline-result.json
```

В поставке нет `__pycache__`, `*.pyc`, `*.pyo`, `*.qmlc`, журналов,
discovery-файлов и результатов временных заданий TopOpt.

## Архитектура

### Командный интерфейс

`AIAssistantTeam` регистрируется как расширение **AI Assistant (команда)**.
QML-интерфейс `Assistant.qml` содержит вкладки «Чат», «Смета»,
«Оптимизация (TopOpt)» и «Настройки». Контроллер связывает QML, LLM и
детерминированные инструменты работы со сценой.

### Headless MCP

Встроенный HTTP MCP-сервер слушает только `127.0.0.1` на свободном порту.
Команды выполняются через JSON-RPC и требуют случайный токен текущего сеанса в
заголовке `X-Session-Token`. Порт и скрытый токен отображаются в «Настройках».
Прокси для loopback в раннере отключён явно.

### Qt-диспетчер

Операции Cura/STE, которым нужен главный поток, проходят через
`ste/qt_executor.py`. Читающие снимки состояния кэшируются, а длительные
операции сцены имеют увеличенный таймаут и повторные попытки. Это предотвращает
блокировку UI при пакетном прогоне.

### 3D и 5D

Для шестерни используется режим `classic` и автоориентация на устойчивую грань.
Для тел вращения применяется `cylindrical_full`. Раннер сравнивает радиальные
габариты по X/Y/Z и автоматически выбирает ось с минимальной разницей. Большое
расхождение фиксируется предупреждением и не обрывает весь прогон.

### Смета и варианты

Экономический модуль использует фактическое время и расход завершённого
слайсинга, тариф станка и цену материала. Исходный и изменённый варианты
хранятся отдельно и сравниваются без подмены инженерных показателей.

### TopOpt

Локальный bridge запускает подготовленный 2D SIMP-шаблон без Ansys и платной
лицензии. Служба имеет discovery-файл, токен, проверку состояния, список
шаблонов, задания, отмену и импорт кандидата. Результат TopOpt является
геометрическим кандидатом; он не заменяет полноценную 3D FEA-валидацию.

### Экспорт файлов

3MF записывается напрямую стандартным `zipfile` как контейнер с геометрией и
метаданными проекта. Нативный `CuraWorkspaceWriter` не вызывается, поэтому
сохранение не блокирует Qt-поток. После записи проверяются существование и
размер файла. G-code извлекается из буфера движка и проверяется по размеру,
движениям и температурным командам. `G28` для профилей Stereotech является
необязательным и при отсутствии создаёт предупреждение.

## Требования

- Windows 10/11;
- Stereotech STE Slicer 7.10;
- CPython 3.8 или новее для внешнего `pipeline_runner.py`;
- сторонние Python-пакеты раннеру не нужны.

Внутренний код плагина сохраняет совместимость со встроенным Python STE Slicer
и использует стандартную библиотеку, PyQt5 и API Cura/STE.

## Установка плагина

1. Закройте STE Slicer.
2. Скопируйте папку `AIAssistantTeam` целиком в:

   ```text
   %APPDATA%\steslicer\7.10\plugins\
   ```

   Итоговый путь должен быть строго:

   ```text
   %APPDATA%\steslicer\7.10\plugins\AIAssistantTeam\plugin.json
   ```

3. Убедитесь, что рядом не установлена старая папка `AIAssistant`, которая
   добавляет простой одноимённый интерфейс.
4. Запустите STE Slicer.
5. Откройте **Extensions → AI Assistant (команда) → Открыть чат**.
6. Проверьте наличие вкладок «Чат», «Смета», «Оптимизация (TopOpt)» и
   «Настройки».

## Пошаговая проверка экспертом

1. Установите `AIAssistantTeam` по инструкции выше.
2. Запустите STE Slicer и выберите рабочий принтер.
3. Откройте **AI Assistant (команда)**.
4. На вкладке **Настройки** скопируйте номер `Port` и временный `Token` MCP.
5. Откройте PowerShell в корне `final_submission`.
6. При необходимости проверьте Python:

   ```powershell
   python --version
   python -m pip install -r .\scripts\requirements.txt
   ```

7. Запустите пакетный прогон:

   ```powershell
   python .\scripts\pipeline_runner.py --url http://127.0.0.1:<PORT>/mcp --token <TOKEN> --config .\scripts\pipeline_models.example.json --results .\results --slice-timeout 180 --http-timeout 120 --overwrite
   ```

8. Не закрывайте STE Slicer до завершения команды. Для каждой модели раннер:
   очищает сцену, загружает STL, выбирает 3D/5D, назначает PLA и быстрый
   профиль, ориентирует модель, запускает реальный слайсинг, сохраняет 3MF и
   G-code и проверяет созданные файлы.
9. Проверьте `results/<model>/pipeline-result.json`. Успешный результат содержит
   `"status": "completed"`.

Токен действует только в текущем запуске STE Slicer. Не публикуйте его и не
добавляйте в отчёт или скриншоты.

## Проверка сохранённых артефактов

- `results/01-gear/project.3mf` — непустой ZIP/3MF-контейнер;
- `results/01-gear/result.gcode` — более 1 КБ, содержит `G1`, команды нагрева
  сопла и стола;
- `results/01-gear/pipeline-result.json` — статус `completed`, абсолютные пути
  в нём относятся к машине, на которой выполнялся подтверждённый прогон.

При повторном запуске с `--overwrite` результаты будут записаны заново уже с
локальными путями проверяющей машины.
