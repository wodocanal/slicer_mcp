# slicer_mcp

Решение для хакатона Моспром: встроенный AI-ассистент для **STE Slicer** и
локальный MCP-сервер с отдельным адаптером **OrcaSlicer**.

## Плагин STE Slicer

Основное конкурсное направление находится в [`ste_plugin/AIAssistant`](ste_plugin/AIAssistant).
Плагин открывает немодальный чат прямо внутри STE Slicer, подключается к
OpenAI-совместимому API, показывает вызовы инструментов и работает с текущей сценой:
режимами 3D/5D, профилями, материалами, параметрами, объектами, слайсингом,
G-code и проектом 3MF.

Готовый установочный архив создаётся командой:

```sh
uv run python scripts/build_ste_plugin.py
```

Результат: `dist/AIAssistant-ste-plugin.zip`. Подробная пошаговая установка,
настройка LLM, проверочные запросы и удаление описаны в
[`ste_plugin/AIAssistant/README.md`](ste_plugin/AIAssistant/README.md).

Исходники проверяются на синтаксис Python 3.5, который используется плагинами
STE. Логика MCP/LLM покрыта автономными тестами. Полный запуск интерфейса,
слайсинга `classic`/`cylindrical`/`cylindrical_full` и экспорта нужно подтвердить
в целевой Windows-сборке STE Slicer 7.10.12 с активированной 5D-лицензией.

## Отдельный MCP для OrcaSlicer

Сервер даёт модели в чате инструменты для чтения профилей, анализа STL,
получения контекста с фотографиями, проверки корректировок параметров и генерации
настоящего G-кода. LLM — модель текущего MCP-клиента; отдельный API-ключ не нужен.

## Быстрый запуск

Требуются Python 3.12+, [uv](https://docs.astral.sh/uv/) и OrcaSlicer.
На macOS CLI уже находится внутри установленного приложения:
`/Applications/OrcaSlicer.app/Contents/MacOS/OrcaSlicer`.

```sh
uv sync --locked
uv run python scripts/configure_codex.py
```

Скрипт создаёт **проектный** `.codex/config.toml` с абсолютными путями к текущему
checkout и его виртуальному окружению. Глобальная конфигурация Codex не изменяется.
Локальный файл исключён из Git; переносимый образец — `.codex/config.example.toml`.
После переноса репозитория в другой каталог нужно обновить локальные пути.

Codex загружает проектные MCP только для доверенных проектов. Откройте новый чат
в этой папке или перезапустите MCP-подключения в клиенте после изменения конфигурации.
У уже работающего чата перечень инструментов может оставаться прежним до перезагрузки.
Конфигурация действует по рабочему каталогу проекта, а не по названию чата.

Проверка регистрации из корня проекта:

```sh
codex mcp get slicer
```

Ручной запуск сервера (ждёт JSON-RPC по stdin, не является HTTP-сервисом):

```sh
uv run slicer-mcp
```

Документация проектной конфигурации:
[Codex MCP](https://developers.openai.com/codex/mcp/).

## Иерархия расширения

```text
SlicerAdapter                 пустая реализация; явные UnsupportedOperation
├── Slicer3D                  общая геометрия и контракт плоской FDM-печати
│   └── OrcaSlicer            профили Orca, проверка параметров, CLI, G-код
└── Slicer5D                  общая геометрия и точка расширения кинематики
    └── будущий адаптер       траектории и проверки конкретной 5D-установки
```

`SlicerService` содержит реестр адаптеров. MCP-слой работает с базовым контрактом
и не строит CLI-команды. Чтобы добавить слайсер:

1. Унаследовать адаптер от `Slicer3D` или `Slicer5D`.
2. Задать уникальное `name`, объявить `capabilities`, переопределить нужные методы.
3. Зарегистрировать экземпляр в `SlicerService` при создании сервера.

Неподдерживаемые операции завершаются явной ошибкой. `Slicer5D` пока не строит
пятиосевые траектории; `submit_print` оставлен точкой расширения. Инструмент
отправки на принтер не публикуется, пока нет реализованного транспорта.

## Инструменты MCP

| Инструмент | Назначение |
|---|---|
| `list_slicers` | Доступность адаптера и поддерживаемые операции |
| `list_profiles` | Поиск профилей принтера, процесса и материала по имени |
| `get_profile` | Настройки с раскрытым наследованием; выбор ключей или `['*']` |
| `analyze_model` | Размеры, площадь, объём и целостность STL |
| `get_model_context` | Анализ STL + промпт + описание + профили + изображения |
| `get_parameter_schema` | Типы, диапазоны и поля допустимых корректировок |
| `plan_parameters` | Проверка предложенных изменений и сравнение до/после |
| `slice_model` | Настоящий слайсинг и пути к G-коду, 3MF, логу и manifest |

Все инструменты адаптера принимают `slicer`, по умолчанию `orca`. Профили читаются
из ресурсов приложения и пользовательского каталога OrcaSlicer. Каталог профилей
кэшируется на время жизни сервера; после добавления профилей перезапустите MCP.
Данные открытой, **несохранённой** GUI-сессии не считываются.

Пример сценария в чате:

> Найди профили Bambu Lab X1 Carbon с соплом 0.4 и Bambu PLA Basic. Проанализируй
> examples/cube_20mm.stl, покажи изменения для четырёх стенок и заполнения 30%,
> затем создай G-код.

Это демонстрационный выбор профиля, а не утверждение о подключённом принтере.
Для реальной детали нужно явно выбрать её принтер и материал.

Аргументы `slice_model` для тестового куба (вместо пути подставьте абсолютный путь):

```json
{
  "request": {
    "model_path": "/absolute/path/to/slicer_mcp/examples/cube_20mm.stl",
    "machine_profile": "builtin:BBL/machine/Bambu Lab X1 Carbon 0.4 nozzle.json",
    "process_profile": "builtin:BBL/process/0.20mm Standard @BBL X1C.json",
    "filament_profile": "builtin:BBL/filament/Bambu PLA Basic @BBL X1C.json",
    "parameters": {
      "layer_height": 0.16,
      "wall_loops": 4,
      "sparse_infill_density": 30
    }
  }
}
```

Та же структура подходит `plan_parameters`. `null` или отсутствие поля сохраняет
значение профиля. Дополнительно доступны `enable_support`, `top_shell_layers`,
`bottom_shell_layers`. Проценты заполнения передаются числом от 0 до 100.
Проверяются типы профилей, явные списки совместимости и высота слоя относительно
сопла. Окончательную валидацию настроек и размещения выполняет Orca.

`get_model_context` принимает `request` с `model_path`, `prompt`, `description`,
`profile_ids` и `photo_paths`. Фото возвращаются как MCP image content, а не только
как имена файлов. Поддерживаются JPEG/PNG/WebP, до четырёх фото по 20 MiB;
изображения уменьшаются до 1600 px, EXIF не передаётся.

## Результаты и воспроизводимость

Каждый слайсинг создаёт `.slicer-mcp/jobs/<id>/`:

```text
model.stl                     копия входной модели
machine.json                  развёрнутые настройки принтера
process.json                  настройки процесса с применённой корректировкой
filament.json                 настройки материала
plate_1.gcode                 готовые команды для выбранного профиля принтера
result.3mf                    проект Orca для ручного просмотра
manifest.json                 запрос, SHA-256 модели, команда, статус и результат
orca.log                      stdout/stderr слайсера
orca-data/                    изолированные данные CLI
```

CLI запускается списком аргументов без shell, с ограничением времени 180 секунд.
Вызов MCP ограничен 240 секундами. При сбое/таймауте manifest получает `failed`;
нулевой exit code без G-кода с движениями экструзии не считается успехом.
Оценки времени и расхода берутся из полученного G-кода. Физическая печать не
запускается. Исходные профили и настройки GUI не перезаписываются.

## Проверки

```sh
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run python scripts/smoke_mcp.py
```

Последняя команда — интеграционная проверка с установленным Orca через настоящий
MCP stdio: initialize, список инструментов, профили, геометрия, фото, проверка
параметров, два слайсинга и проверка изменений внутри G-кода. Она также сравнивает
хеши пользовательских профилей и `OrcaSlicer.conf` до и после. Отчёт сохраняется
в `.slicer-mcp/smoke-report.json`. Нужны стандартные профили BBL из примера выше.

## Границы первой версии

- Входная модель — один STL, до 100 MiB и 2 млн треугольников. Единицы считаются
  миллиметрами. Незамкнутые сетки можно анализировать, но перед слайсингом требуется
  исправление. Автоматический ремонт, оценка тонких стенок и оптимизация ориентации
  пока не реализованы.
- Поддерживаются профили с одним соплом. Размещение на столе автоматическое,
  исходная ориентация сохраняется. Многоматериальная печать и входные 3MF отложены;
  выходной 3MF создаётся.
- Корректировки предлагает модель в MCP-клиенте. Сервер проверяет и применяет их;
  механический расчёт прочности и автоматический поиск оптимума отсутствуют.
- Чтение фото подключено; отдельного классификатора дефектов печати пока нет.
- 5D и управление парком — предусмотренные точки расширения.
- На установленном OrcaSlicer 2.3.1 для macOS CLI может сообщать ошибки
  OpenGL-шейдеров создания миниатюры. Если G-код получен, сервер возвращает результат
  с предупреждением: миниатюра внутри 3MF может отсутствовать.

Настройки окружения: `ORCASLICER_BIN`, `ORCASLICER_PROFILES_DIR`,
`ORCASLICER_USER_DIR`, `SLICER_MCP_WORKSPACE`. Автообнаружение каталогов настроено
для macOS; остальные платформы требуют явных путей и отдельной проверки CLI.
