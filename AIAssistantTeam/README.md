# AI Assistant for STE Slicer

Плагин открывает чат внутри STE Slicer и позволяет LLM управлять подготовкой
3D/5D-печати через проверяемые инструменты. Это изолированная командная копия
версии `0.7.2`, установленная рядом с ранее работавшим плагином.

Состояние на 24 октября 2026 года: командный чат, чтение и изменение настроек,
загрузка моделей, 3D-слайсинг шестерни и экспорт 3MF/G-code проверены в
Windows-сборке STE Slicer 7.10.12. Облегчённое колесо на 64 сегмента также
рассчитано в 5D; исходная выданная сетка колеса остаётся блокером слайсера.
Это технические проверки, не принятые результаты конкурсного набора.
Подробности испытаний команда ведёт отдельно в журнале интеграции.

## Возможности

- Немодальный QML-чат внутри STE Slicer.
- Обновлённое оформление чата и сметы из переданного командой архива; сообщения
  можно копировать кнопкой в чате. Расчётные функции и MCP-инструменты сохранены.
- История диалога, загрузка STL/OBJ/3MF и JPG/PNG.
- OpenAI-совместимый Chat Completions API с tool calling.
- Отображение вызовов инструментов и результатов в чате.
- Чтение и изменение разрешённых параметров печати.
- Выбор режима `classic`, `cylindrical` и `cylindrical_full`.
- Чтение и выбор профилей качества и материалов.
- Загрузка, список, перемещение, поворот, масштабирование, расстановка и удаление
  объектов сцены.
- Автоматический выбор устойчивой плоской стороны детали для обычной 3D-печати:
  сравниваются площадь контакта граней, высота и площадь поверхностей, которым
  может потребоваться поддержка. Поворот и опускание на стол можно отменить.
- Запуск слайсинга, получение времени и расхода, экспорт G-code и проекта 3MF.
- Вкладка **Смета** и MCP-инструменты для расчёта стоимости по завершённому
  слайсингу и тарифам пользователя; отдельные суммы печати, работ вне печати и
  цены заказчику. Можно зафиксировать исходный и изменённый расчёты и увидеть
  разницу. Плагин не меняет настройки при расчёте сметы.
- MCP-инструмент `assess_print_risk` оценивает риски отлипания, геометрии,
  температурного режима, визуальных дефектов и длительной печати. Он сообщает
  основания, неизвестные факторы и рекомендации; оценка не является
  вероятностью брака.
- Инструменты `plan_manufacturing_settings`, `capture_manufacturing_scenario` и
  `compare_manufacturing_scenarios` поддерживают два сценария: быстрый экономный
  прототип для проверки формы и посадки и конечное изделие с приоритетами
  пользователя. Планирование не меняет настройки; каждый сценарий нужно отдельно
  применить и просчитать. После завершения расчёта сохраняются фактические время,
  расход, стоимость по введённым тарифам и предварительная оценка рисков.
  Сравнение показывает разницу. Снимки сценариев живут в памяти текущего сеанса;
  проекты 3MF и G-code сохраняйте отдельно.
- Вкладка **TopOpt · beta** подключает отдельный локальный bridge с
  подготовленным SIMP-шаблоном. Встроенный сценарий строит геометрический
  кандидат для призматической консольной детали по нагрузке и целевой доле
  массы. Ansys и внешняя лицензия не требуются. Это не прочностной сертификат:
  шаблон не рассчитывает полную трёхмерную картину напряжений, усталость и
  коэффициент запаса.
- MCP JSON-RPC endpoint на случайном loopback-порту:
  `http://127.0.0.1:<port>/mcp`, защищённый токеном сессии.

Физическая отправка на принтер не реализована. Агент не должен утверждать
прочность или химическую стойкость без подтверждённых данных.

При запросе «подготовь деталь к печати» в режиме `classic` агент вызывает
`auto_orient_object` после загрузки модели и до слайсинга. Если пользователь
задал ориентацию явно, она сохраняется. Алгоритм не гарантирует минимального
расхода поддержек и не знает, какая поверхность детали должна остаться
косметической или рабочей. Проверьте положение в предпросмотре. Для 5D режимов
автоматическая укладка плоской стороной отключена: положение относительно
цилиндрической оси подбирают отдельно.

## Установка на Windows

1. Установите выданный организаторами STE Slicer 7.10.12.
2. Для проверки режимов 5D активируйте STE Slicer по инструкции организаторов.
3. Запустите STE Slicer и выберите **Справка → Показать папку конфигурации**.
4. Закройте STE Slicer.
5. В открывшейся папке создайте каталог `plugins`, если его ещё нет.
6. Скопируйте папку `AIAssistantTeam` целиком в `plugins`. Итоговый путь должен
   выглядеть примерно так:

   ```text
   %APPDATA%\steslicer\7.x\plugins\AIAssistantTeam\plugin.json
   ```

   Важно: не должно получиться вложения
   `AIAssistantTeam\AIAssistantTeam\plugin.json`.
7. Запустите STE Slicer заново. В верхнем меню появится **AI Assistant (команда)**.
8. Выберите **AI Assistant (команда) → Открыть чат**.

Если плагин не появился, проверьте `stderr.log` и другие `*.log` в папке
конфигурации STE Slicer. Поиск по строке `AI Assistant` обычно показывает ошибку
загрузки или несовместимое API.

## Установка TopOpt bridge

Вкладка **TopOpt · beta** использует отдельный процесс, потому что встроенный
Python 3.5 в STE Slicer не подходит для численного решателя. Рабочая сборка
использует среду `%LOCALAPPDATA%\SlicerMCP\TopOptBridge\.venv`. Для ручной
установки нужен Python 3.12 и NumPy:

```powershell
cd C:\path\to\slicer_mcp\optimization_bridge
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install "numpy>=2,<3"
python server.py --token <СЛУЧАЙНЫЙ_ТОКЕН_НЕ_КОРОЧЕ_32_СИМВОЛОВ>
```

Bridge слушает только `http://127.0.0.1:8765` и создаёт файл
`%LOCALAPPDATA%\Stereotech\TopOpt\connection.json`. При автоматическом запуске
плагин создаёт токен, передаёт его bridge и читает этот файл самостоятельно.
Bridge и STE Slicer должны работать под одним пользователем Windows. Поля URL
и токена скрыты в ручной настройке.
Кнопка **Запустить и проверить TopOpt** сначала проверяет работающий bridge, а
при недействительном токене завершает только процесс из discovery-файла,
очищает устаревшую запись, запускает встроенный сервер и повторяет проверку.
Запущенный процесс закрепляется за STE Slicer через Windows Job Object и
автоматически завершается вместе со слайсером. Журнал находится в
`%LOCALAPPDATA%\Stereotech\TopOpt\bridge.log`.

## Подготовленный шаблон TopOpt

После завершения задания `import_optimized_variant` ждёт появления STL в сцене,
ставит его на рабочую поверхность и размещает рядом с исходными объектами с
зазором 10 мм. Исходные объекты не перемещаются. Если свободного места на
активном столе нет, импортированная копия удаляется и инструмент возвращает
явную ошибку вместо наложения моделей. В координатах сцены STE вертикальной
осью является Y; X и Z лежат в плоскости стола. Для режимов `cylindrical` и
`cylindrical_full` такое размещение не подтверждает правильность ориентации
относительно оси вращения, поэтому перед слайсингом требуется визуальная
проверка.

Границы визуального стола проверяются в координатах сцены STE, где центр
рабочей области находится в `X=0, Z=0`. Параметр профиля
`machine_center_is_zero` относится к машинным координатам экспорта и не смещает
геометрию сцены в диапазон `0…machine_width`.

В поставку входит разрешённый сценарий `topopt_bracket_v1`. Он использует
двумерный SIMP-расчёт: левая сторона области закреплена, вертикальная нагрузка
приложена в середине правой стороны, а целевая доля массы задаётся пользователем.
Исходный STL определяет габариты расчётной области. Его точная топология,
отверстия и рабочие поверхности в этом beta-шаблоне не сохраняются.

```text
optimization_bridge\data\
├── templates\
│   └── topopt_bracket_v1\
│       ├── manifest.json
│       └── topopt_script.py
└── jobs\
```

`topopt_script.py` запускается отдельным процессом и пишет результаты только в
каталог своего задания. Bridge не выполняет произвольный код из чата: доступны
только заранее подготовленные шаблоны. Результат содержит STL-кандидат, историю
сходимости и явный статус `validation: not_performed`. Перед производством
нужны расчёт в инженерной CAE-системе с реальными закреплениями и нагрузками,
проверка технологичности и физические испытания.

## Настройка LLM

1. Откройте **AI Assistant (команда) → Настройки**.
2. Введите `Base URL`, выданный организаторами. Если выдан адрес `/v1`, укажите
   его полностью. Если адрес уже заканчивается на `/chat/completions`, плагин не
   добавляет этот суффикс повторно.
3. Введите API key.
4. Введите точное имя модели, указанное организаторами.
5. Нажмите **Сохранить**.

Ключ сохраняется средствами настроек приложения и не содержится в исходниках,
3MF или G-code. Не добавляйте файл настроек STE Slicer в архив сдачи.

Для первой проверки попросите агента только прочитать состояние:

> Покажи активный принтер, режим печати, материал, профиль качества и объекты
> сцены. Ничего не изменяй.

Затем проверьте изменение, которое легко увидеть и отменить:

> Переключи режим на classic, поставь высоту слоя 0.2 мм и покажи фактическое
> значение после изменения. Слайсинг пока не запускай.

## Работа с файлами

Кнопка **Прикрепить** принимает модели STL/OBJ/3MF и изображения JPG/PNG.
Изображения передаются в LLM как `image_url` с base64. Пути моделей передаются
агенту, после чего он вызывает `load_model`. Загрузка модели в STE асинхронна,
поэтому агент должен после неё вызвать `list_objects` и убедиться, что объект
появился.

Пример полного запроса:

> Проанализируй приложенную модель и ТЗ. Выбери доступные в STE режим, материал
> и профиль. Объясни обязательные ограничения, примени настройки, расположи
> модель, выполни слайсинг и покажи фактическое время и расход. Не экспортируй
> файлы, пока я не попрошу.

Экспорт требует абсолютный путь к существующей папке. Рекомендуется сначала
создать отдельную папку результата, затем попросить сохранить в неё
`project.3mf` и `result.gcode`.

## Локальный MCP

Плагин запускает HTTP-сервер только на `127.0.0.1` и случайном свободном порту.
Порт и токен текущей сессии видны во вкладке настроек. Каждый POST-запрос
должен содержать заголовок `X-Session-Token`. Не публикуйте токен и не храните
его в репозитории. Поддержаны методы:

- `initialize`
- `notifications/initialized`
- `ping`
- `tools/list`
- `tools/call`

Пример запроса списка инструментов:

```powershell
$body = '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
$token = Read-Host 'Токен из настроек командного плагина'
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:PORT/mcp `
  -Headers @{ 'X-Session-Token' = $token } `
  -ContentType application/json -Body $body
```

HTTP-поток не меняет сцену напрямую: инструменты передают работу в главный
Qt-поток и ждут результат. Это необходимо для устойчивости STE Slicer.

## Смета по завершённому расчёту

После статуса `done` откройте **Смета**, нажмите **Обновить**, введите ставку
станка в ₽/час и цену в ₽/кг для каждого использованного экструдера. Для
неиспользуемого экструдера можно оставить поле пустым. При необходимости
отдельно введите работы вне печати с названием, явную надбавку, сумму налогов
и целевой бюджет. Нажмите **Рассчитать**. Пока статус не `done` или тарифы не
указаны, сумма не вычисляется.

Формула внутренней оценки: сумма `масса_i (г) / 1000 × цена_i (₽/кг)` плюс
`время (с) / 3600 × ставка станка (₽/час)`. Материалы округляются по каждому
экструдеру до копейки; машино-часы — отдельно. Работы вне печати, надбавка и
налоги добавляются только как явно введённые суммы. Итоговая цена заказчику
не называется себестоимостью печати. Плагин не знает тарифов, налогообложения
или вероятности брака без данных пользователя.

Для сравнения сначала сохраните проект 3MF, прослайсите исходные настройки и
нажмите **Сохранить исходный**. Затем осознанно измените рабочий проект,
прослайсите заново и нажмите **Сохранить вариант**. Панель сравнит фактические
время, расход, смету и отслеживаемые параметры; она пометит разные тарифы или
разный состав сцены. Это последовательные снимки. Пробные расчёты меняют
живой проект и **не восстанавливаются автоматически**; для отката откройте
сохранённый 3MF. Результаты снимков живут только до закрытия STE Slicer.

Те же действия доступны через MCP: `estimate_print_cost`,
`capture_cost_variant`, `compare_cost_variants`. Они не рассчитывают прочность
и не применяют выбранный вариант автоматически.

## Оценка риска печати

Попросите ассистента оценить риски после выбора материала, ориентации и настроек.
После завершённого слайсинга повторите запрос: тогда в расчёт войдут фактические
время и расход материала. Инструмент `assess_print_risk` использует доступные в
STE сведения о материале, температурах, скорости, высоте слоя, сопле, адгезии,
поверхности стола, поддержках, габаритах и числе объектов.

Площадь контакта первого слоя, длину моста и угол нависания нельзя считать
из одних габаритов модели. Если они измерены или подтверждены осмотром, их
можно явно передать как `observations`. При отсутствии таких данных инструмент
помечает их неизвестными, а не придумывает значения. Результат содержит общий
рейтинг 0–100, категории, причины, рекомендации и полноту исходных данных.
Это сравнительная инженерная оценка, не вероятность отказа и не гарантия печати.
Инструмент ничего не меняет в проекте.

## Разрешённые настройки

Агент может менять только allowlist в `ste/adapter.py`. В него входят режим
печати, слой, стенки, верхние/нижние слои, заполнение, поддержки, адгезия,
температуры, скорости, ретракт, охлаждение и базовые параметры 5D. Ограничение
защищает от произвольного изменения машинного G-code и других чувствительных
настроек. Новые параметры нужно добавлять осознанно и проверять на тестовой
машине.

## Известные ограничения версии 0.7.2

- Код проверен статически на синтаксис Python 3.5; плагин загрузился в
  Windows-дистрибутиве организаторов. Сквозной сценарий ещё проверяется.
- Автоматический выбор сейчас выполняет LLM по ТЗ, геометрии и реально доступным
  профилям. Проверяемая база свойств материалов и перебор ориентаций будут
  следующим этапом.
- Смета зависит от фактических времени и масс, возвращённых STE Slicer после
  расчёта, и от явно введённых тарифов. Поддержки, брак, амортизация и работа
  человека учитываются только тогда, когда пользователь включил их в тариф
  или отдельную строку. Никакого гарантированного числа прочности модуль не даёт.
- `arrange_models` и загрузка моделей асинхронны.
- История хранит текст диалога; изображения повторно не сохраняются и после
  перезапуска не отправляются.
- Ответ API пока не передаётся потоково по токенам. Прогресс показывается общим
  индикатором, а действия инструментов появляются по мере выполнения.
- Создание нового именованного профиля ещё не реализовано; изменения пишутся в
  `userChanges` активного проекта и сохраняются в 3MF.
- Перед конкурсной сдачей обязательны тесты `classic`, `cylindrical` и
  `cylindrical_full` на Stereotech Hybrid 530 V5.2.4.

## Безопасное удаление

Закройте STE Slicer и удалите только папку
`%APPDATA%\steslicer\7.x\plugins\AIAssistantTeam`. Настройки с URL, ключом и историей
останутся в профиле приложения. При необходимости удалите значения с префиксом
`ai_assistant/` из пользовательского файла настроек STE вручную.
